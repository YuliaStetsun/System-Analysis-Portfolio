# getEvents — Метод получения информации по конкретному мероприятию

**URL:** `GET axbit.com/info/{eventId}`

## Входные параметры:

| № | Наименование | Тип данных | Мн-ть | Описание |
| :--- | :--- | :--- | :--- | :--- |
| 1 | eventId | integer | 1..1 | ИД мероприятия |

## Выходные параметры:

| № | Наименование | Тип данных | Мн-ть | Описание |
| :--- | :--- | :--- | :--- | :--- |
| 1 | nameEvent | string | 1..1 | Наименование мероприятия |
| 2 | eventDescription | string | 0..1 | Описание мероприятия |
| 3 | eventDate | string (format date) | 1..1 | Дата проведения мероприятия |
| 4 | location | string | 1..1 | Место проведения мероприятия |
| 5 | eventDateCreated | string (format date) | 1..1 | Дата создания мероприятия |
| 6 | authorId | integer | 1..1 | Идентификатор записи автора мероприятия |
| 7 | authorFirstName | string | 1..1 | Имя автора мероприятия |
| 8 | authorLastName | string | 1..1 | Фамилия автора мероприятия |
| 9 | members | array | 0..* | Сведения об участниках |
| 9.1 | memberId | integer | 1..1 | Идентификатор записи участника |
| 9.2 | memberFirstName | string | 1..1 | Имя участника |
| 9.3 | memberLastName | string | 1..1 | Фамилия участника |
| 9.4 | statusId | integer | 1..1 | Идентификатор записи статуса участия в мероприятии |

## Описание сценария метода:

**Шаг 1.** 
Система валидирует входные параметры на соответствие заявленным типам данных и наличие обязательных входных параметров.
Если проверка не пройдена, система возвращает ошибку **B001**.

**Шаг 2.** 
Система находит запись в таблице `events` по условию:
* `events.id = input eventId`

Если запись не найдена, система возвращает ошибку **B002**.
Если запись была найдена, система переходит к следующему шагу.

**Шаг 3.** 
Система добавляет в выходные параметры следующие значения:
* `nameEvent` = `events.id`
* `eventDescription` = `events.description`
* `eventDate` = `events.date`
* `location` = `events.location`
* `eventDateCreated` = `events.date_created`
* `authorId` = `events.author_id`

**Шаг 4.** 
Система находит запись в таблице `members` по условию:
* `members.events_id = events.id`

Если запись не найдена, система возвращает ошибку **B003**.
Если запись была найдена, система переходит к следующему шагу.

**Шаг 5.** 
*Шаги 5.5-5.* выполняются для каждой найденной записи `members`*

**5.1.** Система добавляет в выходные параметры следующие значения:
* `memberId` = `members.id`
* `statusId` = `members.status_events_id`

**5.2.** Система находит запись в таблице `users` по условию:
* `members.users_id = users.id`

Если запись не найдена, система возвращает ошибку **B004**.
Если запись была найдена, система переходит к следующему шагу.

**5.3.** Система добавляет в выходные параметры следующие значения:
* `memberFirstName` = `users.first_name`
* `memberLastName` = `users.last_name`

**Шаг 6.** 
Система находит запись в таблице `users` по условию:
* `members.users_id = users.id`

Если запись не найдена, система возвращает ошибку **B004**.
Если запись была найдена, система переходит к следующему шагу.

**Шаг 7.** 
Система добавляет в выходные параметры следующие значения:
* `authorFirstName` = `users.first_name`
* `authorLastName` = `users.last_name`

**Шаг 8.** 
Система возвращает выходные параметры и HTTP-код 200.

**Шаг 9.** 
Сценарий завершен.

## Таблица ошибок:

| Код ошибки | HTTP-код | Наименование ошибки | Категория |
| :--- | :--- | :--- | :--- |
| B001 | 422 | Ошибка в валидации входных параметров | BusinessFault |
| B002 | 422 | Мероприятие с event.id = &lt;input eventId&gt; не найдено | BusinessFault |
| B003 | 422 | Участник с members.events_id = &lt;events.id&gt; не найден | BusinessFault |
| B004 | 422 | Пользователь с members.users_id = &lt;users.id&gt; не найден в системе | BusinessFault |
| U001 | 500 | Непредвиденная ошибка | UnexpectedFault |
